# Domain documentation

This repository uses the single-context layout: one root `CONTEXT.md` and
architecture decision records under `docs/adr/`.

Before domain-related exploration, read the context when it exists and any
architecture decisions relevant to the task. If these documents are absent,
proceed without creating placeholders or treating their absence as a blocker.

Use the glossary's vocabulary for domain concepts. Reconsider new terminology
before introducing a synonym or abstraction. Surface conflicts with an existing
architecture decision rather than silently overriding it.
